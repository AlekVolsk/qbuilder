# Безопасность

## Автоматическое экранирование

QueryBuilder **автоматически экранирует** все идентификаторы и значения:

```php
$qb->select('*')
    ->from('users')
    ->where()
        ->eq('name', "O'Brien")
        ->end();

// WHERE (`name` = 'O''Brien')  - автоматически экранировано
```

Кавычка экранируется удвоением (`''`) — литерал нельзя закрыть досрочно ни в одном режиме сервера. Обратный слэш удваивается (`\\`), потому что в режиме MySQL по умолчанию он служебный. Управляющие символы (`\n`, `\r`, `\0`) передаются как есть — внутри литерала они допустимы.

**MySQL и `NO_BACKSLASH_ESCAPES`.** Билдер не знает `sql_mode` сервера. В этом режиме обратный слэш — обычный символ, поэтому удвоенный `\\` запишется в данные как два слэша. Инъекции при этом нет (проверено на MySQL 8.0 в обоих режимах), но значения с обратным слэшем исказятся — не включайте этот режим для соединений, через которые идёт SQL билдера.

**PostgreSQL.** Значение с обратным слэшем оформляется как `E'...'`: в такой строке обратный слэш экранирующий при любом `standard_conforming_strings`, поэтому `C:\dir` сохраняется без искажений и в режиме `on` (по умолчанию), и в устаревшем `off`. Значения без обратного слэша остаются обычными `'...'`.

## Форматирование значений по типу

Вид литерала определяет PHP-тип значения, а не его содержимое. Правило одно для условий, INSERT/UPDATE, upsert/merge и параметров процедур:

| PHP-тип | Литерал | Пример |
|---|---|---|
| `int`, `float` | без кавычек | `42`, `1.5` |
| `string` | всегда в кавычках, даже если похожа на число | `'0123456789'`, `'1e3'` |
| `bool` | литерал драйвера | `1` / `0`; PostgreSQL — `TRUE` / `FALSE` |
| `null` | `NULL` | `NULL` |

Строка с ведущими нулями (ИНН, коды, артикулы) сохраняется без искажений. Число, пришедшее строкой (например, из `$_GET`), уходит в кавычках — сравнение `int`-колонки с `'5'` СУБД выполняют корректно. Чтобы передать число, приведите тип: `(int) $_GET['id']`.

`INF` и `NAN` не имеют SQL-литерала — `formatValue()` бросает `InvalidQueryException`.

```php
$qb->insert('org')
    ->insertRow(['inn' => '0123456789', 'qty' => 5, 'active' => false])
    ->build(true);

// INSERT INTO `org` (`inn`, `qty`, `active`) VALUES ('0123456789', 5, 0)
```

## Защита от SQL-инъекций

**✅ ПРАВИЛЬНО** - использование QueryBuilder:

```php
$userInput = $_GET['status'];

$qb->where()
    ->eq('status', $userInput)
    ->end();

// Значение будет экранировано автоматически
```

**❌ НЕПРАВИЛЬНО** - НЕ используйте конкатенацию строк:

```php
$userInput = $_GET['status'];
$sql = "SELECT * FROM users WHERE status = '" . $userInput . "'";
```

## Валидация идентификаторов

QueryBuilder проверяет имена таблиц, полей и алиасов:

```php
$qb->from('users');          // ✅ OK
$qb->from('users; DROP--');  // ❌ Exception: Invalid table name
```

## Зарезервированные слова

Зарезервированные слова SQL автоматически экранируются:

```php
$qb->from('fields');  // ✅ OK - будет экранировано как `fields`
$qb->from('order');   // ✅ OK - будет экранировано как `order`
```

## Опасные функции

QueryBuilder **блокирует** опасные SQL-функции:

```php
$qb->from('LOAD_FILE');        // ❌ Exception
$qb->from('INFORMATION_SCHEMA'); // ❌ Exception
```
